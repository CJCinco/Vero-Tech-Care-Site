# AGENTS.md  
  
## Purpose  
This repository powers the Vero Tech Care website.  
  
Vero Tech Care is a premium local tech-help business. The site should feel:  
- premium  
- minimal  
- modern  
- calm  
- trustworthy  
- direct  
- high-value without being salesy  
  
Primary audience:  
- older adults, especially 55+  
- local households in and around Vero Beach  
- people who value patience, clarity, trust, and white-glove help  
  
Core brand framing:  
- white-glove tech care and peace of mind  
- patient, simple, reliable help  
- outcomes over technical jargon  
- premium service, not discount computer repair  
  
## Core site objective  
The website should guide visitors toward one primary action:  
  
**Book Online**  
  
The embedded Acuity scheduler is the primary booking path.  
  
Phone, text, and email should remain available, but only as secondary contact methods for:  
- questions before booking  
- help choosing the right appointment  
- unusual or complex situations  
- membership questions  
- workshop, partner, or community inquiries  
  
Do not frame phone, text, or email as the main way to book unless explicitly requested for a specific task.  
  
## Editing principles  
When making changes:  
- keep the current design language intact  
- preserve the site's premium minimal feel  
- make the smallest clean set of edits needed  
- avoid unnecessary redesigns  
- avoid adding visual clutter  
- avoid adding long blocks of copy  
- preserve responsiveness and accessibility  
- preserve existing functionality unless the task explicitly requires changes  
  
Prefer:  
- concise copy  
- clear hierarchy  
- fewer sections  
- fewer competing CTAs  
- strong whitespace  
- simple, obvious user flow  
  
Avoid:  
- overexplaining  
- hype language  
- marketing fluff  
- too many buttons in the same section  
- repeating the same information in multiple sections  
- jargon-heavy copy  
  
## CTA rules  
Default primary CTA language:  
- Book Online  
  
Acceptable secondary CTA language when context requires specificity:  
- Schedule your appointment  
- Book Remote Session  
- Book In-Home Visit  
- Ask About Memberships  
  
Do not use these as primary booking language unless explicitly requested:  
- Call today  
- Text to book  
- Email to book  
- Reach out to schedule  
  
If a page or section needs a secondary support line, prefer:  
- Questions before booking? Call, text, or email.  
- Not sure what to book? Contact me and I’ll point you in the right direction.  
  
## Copy style  
Copy should be:  
- brief  
- calm  
- professional  
- human  
- easy to skim  
- friendly but not chatty  
- simple enough for non-technical users  
  
Write for clarity first.  
Use minimal jargon.  
Favor short sentences.  
Favor plain English over clever wording.  
  
The tone should feel premium and reassuring, not flashy or over-enthusiastic.  
  
## Audience guidance  
Assume many visitors may:  
- feel intimidated by tech  
- want reassurance before booking  
- prefer simplicity over too many choices  
- value trust signals  
- appreciate clear pricing and clear next steps  
  
When editing copy:  
- reduce friction  
- reduce ambiguity  
- reduce decision fatigue  
- make the next step obvious  
  
## Conversion guidance  
The site should generally follow this flow:  
1. trust / positioning  
2. clear booking action  
3. simple pricing clarity  
4. services overview  
5. FAQ / reassurance  
6. contact for exceptions  
  
The scheduler should usually appear high on the page.  
Keep the booking flow direct.  
Do not create multiple competing booking paths.  
  
## Pricing guidance  
Pricing should support premium positioning and qualification.  
  
Default service pricing:  
- $125/hr minimum  
- 2-hour minimum for in-home  
- evenings/weekends may carry a surcharge  
- travel beyond the standard service area may carry a premium  
- memberships begin at premium price points and should not feel bargain-tier  
  
When showing pricing on the site:  
- keep it concise  
- use simple starting-price language when possible  
- avoid large complex pricing sections unless explicitly requested  
- do not undercut the premium positioning  
  
## Scope and messaging guardrails  
This is not a bargain tech-repair brand.  
Do not rewrite the site to sound cheap, generic, or mass-market.  
  
Do not position the business like:  
- a discount repair shop  
- a big box tech desk  
- a generic MSP  
- a corporate IT provider  
  
Prefer language that emphasizes:  
- in-home convenience  
- patient guidance  
- peace of mind  
- clear explanations  
- reliable outcomes  
- local trust  
  
## Design guardrails  
Unless explicitly requested, do not:  
- change brand colors  
- change typography system  
- change imagery style  
- replace the visual identity  
- add trendy effects  
- add unnecessary animations  
- add dense cards or crowded layouts  
  
Small spacing, alignment, and consistency improvements are encouraged when needed.  
  
## Section guidance  
When simplifying pages, prefer:  
- keeping the scheduler  
- keeping services  
- keeping FAQ  
- keeping contact  
- compressing or removing redundant sections  
- shortening long sections before redesigning them  
  
If a section becomes redundant because of a new booking flow, compress it or remove it instead of rewriting it at length.  
  
## Technical guidance  
Before making edits:  
- inspect the existing structure and reuse components/classes where possible  
- avoid unnecessary abstractions  
- keep code readable  
- keep changes localized  
- avoid touching unrelated files  
  
When changing CTAs:  
- update repeated CTA text consistently  
- update link targets consistently  
- preserve semantic HTML  
- preserve keyboard accessibility  
- preserve mobile usability  
  
## Validation checklist  
Before finishing any task, verify:  
- the main CTA is clear  
- booking flow is consistent  
- no old booking language remains unintentionally  
- layout still feels clean  
- mobile wrapping still looks good  
- spacing still feels premium  
- no unnecessary copy was introduced  
- contact methods remain available but secondary  
  
## Preferred working style for this repo  
For this site, favor:  
- high-confidence edits  
- minimal changes with clear payoff  
- practical UX improvements  
- only recommendations or edits likely to create meaningful impact  
  
Avoid endless tinkering.  
Ignore tiny low-value changes unless they clearly improve flow, clarity, or conversion.
